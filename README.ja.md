# goals-iterm-mcp

[English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | 日本語

**コーディングエージェントで Mac 上の CLI を操作。スマートフォンからでも開発を進められます。**

goals-iterm-mcp は **iTerm2 の Python API** を通じて、MCP 対応エージェントを Mac 上のターミナルに接続します。会話でタスクを伝えると、エージェントがターミナルウィンドウを開き、プロジェクト内で別のコーディング CLI を起動し、指示を送り、進捗や結果を読み取れます。複数のプロジェクトや CLI セッションで進める vibe coding の作業を、ターミナルを手動で切り替えずに調整できます。

## できること

- **スマートフォンから作業を続ける**：エージェントのモバイル版やリモート接続を通じて、Mac 上の iTerm2 に作業を指示できます。接続先のエージェントがローカル MCP にアクセスできることが条件です。
- **コーディング CLI を連携させる**：Claude Code、Codex CLI などを起動し、プロジェクトを選んで開発や調査のタスクを送れます。
- **会話で進捗を確認する**：ウィンドウやタブの一覧、ターミナル出力を読み取り、各セッションの状況を要約できます。
- **プロジェクトごとにセッションを分ける**：専用のウィンドウやタブを作成し、明示的な ID で操作対象を指定できます。
- **目標の達成までほかの CLI を継続的に指導する**：Codex や Claude などの監督役のエージェントに、目標と明確な完了条件を与えます。エージェントはこの MCP でほかの CLI セッションを確認し、進捗を判断し、追加の指示を送り、結果を検証するサイクルを繰り返せます。目標の管理と継続実行は監督役のエージェントが担い、この MCP はターミナルへのアクセスを提供します。

想定する流れは、**スマートフォンまたはデスクトップでの会話 → ローカル MCP にアクセスできるエージェント → iTerm2 → コーディング CLI** です。Codex、Claude、Cursor、WorkBuddy、Trae、Hermes など、利用するクライアントがローカル stdio MCP と必要なモバイル・リモート接続に対応していれば、この構成を使えます。手動検証では Codex デスクトップから iTerm2 内の Claude Code と Codex CLI を操作しました。

たとえば、監督役のエージェントに次の目標を伝えます。

> プロジェクト専用の iTerm セッションで動くコーディング CLI を、ログイン問題の原因調査、修正、関連テストの合格まで継続的に指導してください。各段階で進捗を確認し、必要に応じて追加の指示を送り、最後に完了条件と結果を照合してください。実行中のタスクを重複して送らないでください。この範囲を超える判断が必要な場合は私に確認し、完了時に変更内容とテスト結果を報告してください。

`serve` コマンドは、セッション一覧の取得、ターミナル出力の読み取り、テキストとキーの送信、ウィンドウとタブの作成、セッションの命名を行う 8 つの stdio MCP ツールを提供します。

## 事前準備

### iTerm2 Python API を有効にする

macOS 上で iTerm2 をインストールし、起動しておく必要があります。このプロジェクトは **iTerm2 3.7.6** で検証済みです。

1. **iTerm2 → Settings → General → Magic** を開きます。
2. **Python API** を有効にします。
3. MCP サーバーの初回接続時に iTerm2 の API 認可ダイアログが表示された場合は、接続を許可します。
4. MCP ツールの使用中は iTerm2 を起動したままにします。

詳しくは [iTerm2 公式設定ドキュメント](https://iterm2.com/documentation-preferences-general.html)を参照してください。

### コーディング CLI を設定する

iTerm2 経由でコーディング CLI を操作する前に、その CLI をインストールし、iTerm 環境で認証を設定してください。OAuth ログインを完了するか、CLI が対応する方法で API Gateway のエンドポイントと認証情報を設定します。まず iTerm2 で手動起動し、簡単なプロンプトに応答できることを確認してください。

新しい iTerm ウィンドウやタブにも必要な設定が引き継がれるようにしてください。goals-iterm-mcp はターミナルを操作し、各 CLI は自身の認証と API 設定を使用します。認証情報は CLI が対応する認証情報ストアやローカル設定に保存し、エージェントへのプロンプトには含めないでください。

## uvx で実行する

バージョン 0.1.2 は [PyPI](https://pypi.org/project/goals-iterm-mcp/) で公開されています。リポジトリをクローンせずに実行できます。

```sh
uvx --python 3.12 goals-iterm-mcp@0.1.2 serve
```

Python のインポートパスは `goals_iterm_mcp`、コマンド名は `goals-iterm-mcp` です。

以下のプロンプトを、ローカルコマンドの実行と MCP クライアントの設定ができるエージェントに渡してください。`[MCP クライアント]` は Codex デスクトップや Claude Code など、実際に使うクライアント名に置き換えます。ローカルの macOS へのアクセスが必要です。クラウドのみで動作するチャットからは、ローカルの iTerm2 に接続できません。

```text
PyPI から goals-iterm-mcp 0.1.2 をインストールし、[MCP クライアント] に設定してください。
リポジトリ：https://github.com/lucky-goals/goals-iterm-mcp

1. このコンピューターが macOS で、iTerm2 がインストール済みかつ起動中であることを
   確認してください。uv/uvx がなければ、uv の公式手順でインストールしてください。
   Python 3.12 を使い、リポジトリのクローンやプロジェクトの .venv は不要としてください。

   uvx --python 3.12 goals-iterm-mcp@0.1.2 --help
3. クライアントの既存の MCP 設定を確認し、無関係な設定を保持してください。
   ユーザーレベルの設定で、iterm という名前の stdio サーバーを追加または更新し、
   重複を避けてください。
   command：このコンピューター上の uvx の絶対パス
   args：["--python", "3.12", "goals-iterm-mcp@0.1.2", "serve"]
   クライアントが対応する設定形式と場所を使ってください。編集前に既存の設定を
   バックアップし、ほかのサーバーは変更しないでください。
4. 必要に応じて iTerm2 Python API の有効化と認可ダイアログの承認を案内してください。
   クライアントが対応する方法で MCP 接続を再読み込みしてください。
   私が手動でクライアントを再起動する必要があれば、明確に伝えてください。
5. MCP ハンドシェイク、インストール済みバージョンのツールの検出、読み取り専用の list_sessions 呼び出しを
   確認してください。インストール確認では、ターミナル入力の送信、セッション内容の

6. 設定ファイルの場所、起動コマンド、検証結果を報告してください。
```

この公開パッケージのインストールに PyPI アカウントや API トークンは不要です。上記の設定ではインストール済みバージョンのすべてのツールが提供されますが、インストール確認ではセッション一覧の取得のみを行います。

## インストールと起動

上記の[事前準備](#事前準備)を済ませてください。ソースからのインストールには Python 3.12 が必要です。リポジトリのディレクトリで実行します。

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements.lock
.venv/bin/python -m pip install --no-build-isolation --no-deps -e .
.venv/bin/python -m goals_iterm_mcp serve
```

`serve` は stdin/stdout で MCP プロトコルのメッセージを待ち受けます。対話型シェルではありません。診断情報は stderr に出力されます。Python の自動再読み込みを使わずに実行してください。

MCP クライアントの設定例です。コマンドのパスを実際の絶対パスに置き換えてください。

```json
{
  "mcpServers": {
    "iterm": {
      "command": "/absolute/path/to/goals-iterm-mcp/.venv/bin/python",
      "args": ["-m", "goals_iterm_mcp", "serve"]
    }
  }
}
```

オプション：

- `--read-only`：セッション一覧と読み取りツールのみを公開します。
- `--session-id <ID>`：指定したセッションへのアクセスに制限します。複数回指定できます。この制限が有効な間は、ウィンドウとタブの作成が無効になります。

デフォルトでは、現在のユーザーのすべての iTerm セッションを操作できます。読み取りや送信には、必ず `list_sessions` が返した正確な `session_id` を指定します。フォーカスやタイトルから対象を推測することはありません。

## MCP ツール

| ツール | パラメーター | 説明 |
| --- | --- | --- |
| `list_sessions` | なし | セッション、タブ、ウィンドウの ID、読みやすい `name` とメタデータを一覧表示します。 |
| `read_screen` | `session_id` | 描画済みの画面行、サイズ、カーソル位置を読み取ります。 |
| `read_history` | `session_id`, `lines=100` | 保持されているスクロールバックを最大 2,000 行読み取ります。 |
| `send_text` | `session_id`, `text` | 最大 16 KiB のテキストをそのまま送信します。改行は追加しません。 |
| `send_keys` | `session_id`, `key` | ターミナルのキーシーケンスを 1 つ送信します。 |
| `create_window` | `command`（省略可） | デフォルトプロファイルでウィンドウを作成し、ID を返します。起動コマンドも指定できます。 |
| `create_tab` | `window_id`, `command`（省略可） | 指定したウィンドウにタブを作成します。起動コマンドも指定できます。 |
| `rename_session` | `session_id`, `name`（省略可） | 既存のセッションを改名します。`name` を省略すると未使用のニックネームをランダムに選びます。 |

`create_window` または `create_tab` で作成したセッションには、4〜7 文字の異なる 200 個の名前からランダムなニックネームが自動で割り当てられます。既存のセッションには `rename_session` で名前を付けられます。指定する名前は最大 64 文字で、大文字と小文字を区別せずに重複を確認します。ほかの稼働中セッションが使用している名前は重複して割り当てられません。セッションを閉じると、その名前を再利用できます。名前の候補を使い切った場合は、セッションを作成する前にエラーを返します。

会話でニックネームを指定して操作する場合、まず `list_sessions` で対応する正確な `session_id` を取得し、その ID を操作ツールに渡します。

対応するキー：`enter`、`tab`、`escape`、`backspace`、`up`、`down`、`left`、`right`、`ctrl_c`、`ctrl_d`、`ctrl_u`、`ctrl_l`。

テキスト内の改行、Enter、制御キーはフォアグラウンドのプログラムが解釈するため、コマンドの実行やプログラムの終了につながる場合があります。送信には `suppress_broadcast=True` を指定し、対象のセッションだけに送ります。応答の `api_acknowledged` は iTerm API の呼び出し確認を示すもので、コマンドの完了状態は `unknown` のままです。失敗やタイムアウト時に自動再送は行いません。

画面と履歴の読み取りは、ターミナルに描画された出力を返します。CLI 内部のエディターのテキストや、生の PTY バイト列ではありません。ツール操作は単一のサーバープロセス内で直列化されますが、ほかの MCP プロセスや手動入力とは調整されません。サーバーを終了すると API 接続のみが切断され、ユーザーのセッションは閉じられません。

## 検証

現在の自動テストを実行するには：

```sh
.venv/bin/python -m unittest discover -s tests -v
```

2026 年 10 月 17 日時点で、接続初期化時のリソース解放の修正後、全 69 件の自動テスト、Ruff チェック、依存関係チェック、wheel ビルドが成功しています。[テスト記録](docs/test-results.md)を参照してください。

実際の stdio MCP → iTerm Python API 接続では、ウィンドウとタブの作成、テキストと Enter の送信、中国語と絵文字の画面出力、空でないスクロールバックの読み取りを検証しました。作成した 2 つの一時テストセッションは検証後に閉じています。

新規作成した `/bin/cat` セッションだけを操作する実機スモークテストは、次のように再現できます。

```sh
.venv/bin/python scripts/smoke_iterm.py         # 実行計画のみ表示
.venv/bin/python scripts/smoke_iterm.py --run   # 専用セッションを作成し、テスト後に閉じる
```

## プロジェクト構成

実行時のモジュールは、MCP ツール、iTerm バックエンド、読み取り結果の型、カーソル座標の変換、トランザクション、接続のクリーンアップを担当します。以前の broker/gateway、管理 UI、CLI 認定、実験的な実装は削除済みです。

残した機能と削除した機能の判断理由は[依存関係と整理の記録](docs/cleanup-plan.md)、モジュール単位の調査結果は[依存関係一覧](docs/cleanup-dependencies.json)を参照してください。
